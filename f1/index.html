01 / 시연

실기기 플레이 영상

레이스가 방 안의 디오라마가 됩니다.

  • 여러 차량하나의 레이스 시간축에서 함께 움직입니다.
  • 이벤트 연출선택 구간을 별도의 리플레이 장면으로 구성합니다.
  • MR 배치패스스루로 보이는 실제 공간 위에 스테이지를 놓습니다.

03 / 담당

개인 기여 범위

Quest 3 통합과 companion backend를 맡았습니다.

01

Quest 3 실행 환경·MR 통합

Unity 프로젝트의 Quest 3 실행 환경과 패스스루 기반 MR 장면을 연결하고, 리플레이 스테이지가 실제 공간에서 동작하도록 실기기 통합을 담당했습니다.

02

Companion Replay Backend

Unity가 레이스 목록과 재생 데이터를 단계적으로 가져갈 수 있도록 catalog·dataset·manifest·chunk REST API를 구성했습니다.

04 / 기술 문제

세 가지 핵심 설계

데이터의 진실을 지키면서 공간 경험으로 바꿨습니다.

  1. 01

    차량별 데이터를 하나의 레이스처럼 재생하기

    문제 차량마다 나뉜 데이터를 개별 재생하면 같은 순간의 레이스가 어긋납니다.

    해결 모든 차량을 source-time 기준의 공통 시계에 연결하고 pause·speed·seek를 한곳에서 제어했습니다.

    결과 여러 차량이 같은 레이스 순간을 기준으로 움직입니다.

  2. 02

    레이스 좌표를 방 크기의 디오라마로 옮기기

    문제 원본 좌표를 그대로 쓰면 실제 방에서 보기 어렵고, 점마다 수정하면 트랙 형태가 달라집니다.

    해결 이벤트 로컬 트랙은 유지한 채 Hero를 기준으로 위치·회전·균일 스케일을 적용했습니다.

    결과 리플레이 형상을 보존하면서 방 안에 배치할 수 있습니다.

  3. 03

    변하는 AR Plane 위에서 배치를 안정적으로 유지하기

    문제 공간 스캔 중 plane이 갱신되면 사용자가 고른 벽과 바닥을 잃을 수 있습니다.

    해결 먼저 동일 plane을 찾고, 필요할 때만 제한된 조건으로 재획득한 뒤 확정 후 레이아웃을 고정했습니다.

    결과 설정 중 변화에는 대응하면서 플레이 중 불필요한 재배치를 줄였습니다.

03

공간 프레젠테이션

리플레이 로직과 방 안의 위치·회전·스케일을 분리합니다.

구현 경계 자세히 보기

이벤트 프레젠테이션 루트인 EventReplayStage가 Hero 중심의 위치·회전·균일 스케일을 소유하고, VisualMotionRoot는 차량의 시각적 움직임과 표현을 담당합니다.

데이터 경로는 catalog → dataset → manifest → chunk 순서이며, Unity 클라이언트는 준비 상태에 맞춰 재생 데이터를 가져옵니다.

06 / 공간 배치

Entry · Hero · Exit

Hero를 기준으로 이벤트 스테이지를 놓습니다.

Entry Hero Exit

Entry·Hero·Exit는 공간 구성을 위한 미리보기 지점입니다. 현재 런타임 경로가 차량의 Entry·Exit 통과를 보장한다는 뜻은 아닙니다.

기술 상세 및 검증 기록

데이터 범위

companion backend가 준비한 과거 레이스 데이터셋을 사용합니다. Unity 앱이 OpenF1에 직접 또는 실시간으로 연결되는 구조는 아닙니다.

공간 범위

선택 이벤트의 로컬 트랙을 Hero 중심으로 배치합니다. 전체 트랙의 방 매핑이나 Entry·Exit 통과를 보장하지 않습니다.

시연 범위

영상은 Quest 3 테스트 세션의 실행 장면입니다. 성능 벤치마크나 모든 공간에서의 동작 보증으로 제시하지 않습니다.

실험 기능

일부 이벤트 연출과 공간 미리보기 경로는 프로토타입 또는 실험 상태입니다. 핵심 리플레이·공통 시간축·Hero 중심 배치와 구분합니다.
